Priority order and completion criteria:
1. Per-video/job isolation
   - Tracking, keypoint, assignment caches, and default outputs cannot collide across different videos/jobs.
   - Cache invalidation works when an upload is replaced at the same path.
2. Court keypoint and homography reliability
   - Invalid/insufficient keypoints and rejected homographies are detectable in logs or diagnostics.
   - Failure/fallback behavior is safe, bounded, and covered by focused tests.
3. Automatic team discovery
   - Normal use does not require hard-coded "white jersey"/"dark jersey" descriptions.
   - Team identity/colors are inferred or configurable with a robust fallback.
   - Red and white jerseys must not be grouped together because of brightness,
     skin, court, background, shadows, or jersey-number pixels.
   - Sample a focused upper-torso jersey region using a color space suited to
     color separation (for example HSV or Lab), robust pixel filtering, and
     multiple observations per tracked player.
   - Do not classify a player's team from one raw BGR mean crop.
   - Add focused tests with synthetic red/white jersey crops, lighting changes,
     dark skin/background pixels, and noisy observations.
   - Reject or down-weight low-quality observations: partial/edge-of-frame boxes,
     occlusion, blur, tiny torso regions, excessive background, and weak distance
     margins between team prototypes.
   - Invalid or ambiguous features must produce an unknown observation, not
     silently default to team 1.
   - Produce an explicit video/job-level discovery confidence from prototype
     separation, cluster support, observation quality, and track agreement.
   - If reliable automatic discovery is not possible, return a structured
     `needs_team_colors` result instead of guessing, silently falling back to
     hard-coded descriptions, or rendering misleading team analytics.
   - Add a pre-analysis configuration path (CLI first if no upload UI exists)
     that accepts both teams' primary jersey colors, ideally as color-picker or
     swatch values plus optional team labels. Validate that both colors are
     present, normalized, and sufficiently distinct.
   - User colors guide the two prototypes but do not bypass observation-quality
     checks, ambiguity margins, unknown states, or track-level aggregation.
   - Store assignment mode (`automatic` or `user_colors`) and normalized colors
     in job metadata. Include them and an assignment-algorithm version in the
     assignment cache key so changing color inputs recomputes assignments while
     retaining expensive tracking/keypoint caches.
   - Add focused tests for low-confidence discovery, the `needs_team_colors`
     response, color validation, deterministic team-ID mapping, and selective
     assignment-cache invalidation.
4. Team assignment stability
   - A tracked player's team does not flicker frame-to-frame from noisy classifications.
   - Temporal voting/confidence behavior has focused tests.
   - Cached assignments must be versioned or invalidated when classification
     logic changes so an old incorrect team assignment is not silently reused.
   - New tracks must not emit a confident team from weak early evidence.
   - Prefer a track-level confidence model using several high-quality samples;
     once established, apply that result consistently to earlier frames when
     processing an offline video.
5. Ball possession reliability
   - Missing/noisy ball detections do not create rapid false possession changes.
   - Possession smoothing and unknown states are explicit and tested.
   - Team-possession percentages are derived from verified possession segments and
     valid team assignments, use a documented denominator, exclude or report
     unknown/no-holder frames consistently, and match displayed overlays.
   - Validate intermediate possession ownership against source footage; do not
     accept a plausible final percentage when the underlying segments are wrong.
6. Pass and interception reliability
   - Events require stable possession transitions and valid team assignments.
   - Duplicate/false events across unknown gaps are prevented and tested.
7. Speed and distance reliability
   - FPS, court dimensions, homography validity/fallback, coordinate scale, and
     elapsed-time calculations are explicit and tested.
   - Stationary players remain near zero; track gaps, camera motion, identity
     changes, or homography jumps do not create implausible speed/distance spikes.
   - Invalid tactical coordinates produce unknown/unavailable measurements rather
     than fabricated values, and rendered overlays agree with computed data.
   - Validate representative stationary, walking, running, gap, and homography-
     transition sequences against all three source videos.
8. Deployment readiness
   - Large model assets are never committed.
   - Missing models fail with actionable setup guidance.
   - Runtime dependencies and startup behavior are reproducible.
